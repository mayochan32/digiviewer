# DigiViewer 0.6.0 Windows PC 動作確認指示

対象はDigiViewer 0.6.0の種名推測追加版。写真の管理・公開ソフトは別製品であり、DigiViewerの前提条件にしてはいけない。両方を同じPCにインストールして使うことはできる。

この文書は検証時の手順です。2026-09-22にWindows CPU版の実機検証結果を確認しました。[確認結果と受け入れ判断](windows-0.6.0-review.md)を参照してください。判定中の強制終了によるPython残留については、利用者の指定により注意事項を記載して許容する扱いに変更しました。以下の終了試験・最終判定にもこの例外を適用します。その他の未実施項目は合格扱いしません。

Macではビルド・通常テスト・専用Python導入・CPU/MPS判定を確認済みです。

## 1. 確認する版を用意する（ビルド担当）

今回の変更は未コミットのため、古いリポジトリの取得だけでは含まれない。添付の `DigiViewer_0.6.0_source.zip` と同名の `.sha256` を使う。これはソースであり、インストーラーではない。以前の0.5.5配布物や `species-option-preview` の古い確認用アプリを使わない。

既存のWindows開発環境（Node.js 22以上、Rust、Tauri用MSVC/Windows SDKが準備済み）で展開して実行する。開発環境がない利用者PCに、今回の動作確認のためだけにPython・Node.js・Rust・ドライバーを追加しない。必要なら開発環境のある別PCでビルドし、生成したインストーラーを利用者PCに渡す。

```powershell
Get-FileHash .\DigiViewer_0.6.0_source.zip -Algorithm SHA256
Expand-Archive .\DigiViewer_0.6.0_source.zip -DestinationPath .\DigiViewer-0.6.0-check
cd .\DigiViewer-0.6.0-check\digiviewer-0.6.0
npm ci
node --test tests/project.test.mjs
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --lib --locked
npm run tauri build -- --bundles nsis
```

ハッシュを添付ファイルと照合する。ビルド失敗時はエラーを記録して停止し、古いexeに置き換えない。生成された `src-tauri\target\release\bundle\nsis\` 内の0.6.0インストーラーとそのSHA-256を記録する。GitHubへの公開・push・リリース作成はこの指示に含まない。

通常のテストで `native_install_and_offline_inference` がignoredなのは仕様。この自動テストは特定写真を必要とするため、Windowsでは以下の画面操作で実写真を確認する。

## 2. PCと初期状態を記録する

- Windowsの版・ビルド、x64であること、CPU、RAM、空き容量、GPU名とドライバーバージョン。
- RAM16GB以上、空き15GB以上を目安。CPU版から始める。
- DigiViewerを起動して画面の版が0.6.0であること。旧版からの更新の場合、文字サイズ・通常の設定が残ること。
- テストには元写真のコピーを使う。JPEG・PNG・WebP、鳥・昆虫、不鮮明な写真、日本以外の写真があれば用意する。日本語と空白を含むフォルダー名も含める。
- 比較用のJPEG＋同じ名前のRAWのコピーを別途用意する。元の写真や既存レビューは変更しない。

DigiViewer本体のインストール後、種名推測を導入する直前に、利用者・システムのPATH、`where.exe python` / `where.exe py`、既存Pythonの版、Python関連レジストリの有無を記録する。既存PythonがないPCでは「なし」を正常な基準値とする。確認のためにPythonをインストールしたり、Microsoft StoreのPythonエイリアスを起動したりしない。

Python関連レジストリは読み取りだけで確認する。

```powershell
[Environment]::GetEnvironmentVariable('Path','User')
[Environment]::GetEnvironmentVariable('Path','Machine')
where.exe python
where.exe py
reg query HKCU\Software\Python /s
reg query HKLM\Software\Python /s
reg query HKLM\Software\WOW6432Node\Python /s
```

存在しないキーやコマンドのエラーはそのまま「導入前から存在しない」と記録する。ログに含まれるユーザー名・個人のパスは共有前に伏せる。

## 3. 単体利用と標準機能

写真の管理・公開ソフトをインストールしていないPCで確認するのが最も確実。用意できない場合は相手ソフトと開発サーバーをすべて終了し、「同居PCで相手を停止した検証」として区別する。単体PCの検証を済んだことにしない。

1. DigiViewerを普通に起動する。ブラウザー・管理画面・ポート8787/8789・ソースフォルダーへの接続を求めないこと。
2. 設定の種名推測が初回は「未導入」。種名推測を入れなくても写真表示、比較、拡大、レビュー、既存の種名付加が使えること。
3. 本体のインストール後は、ビルド用ソース・Node.js・Rust・別ソフトを起動していなくても動くこと。開発ツールをわざわざアンインストールする必要はない。

## 4. 設定からCPU版を導入

1. 「設定 → 種名推測」でCPUを選び、「無料の追加機能を導入」を押す。
2. 導入状況が表示され、完了後に「導入済み・無効」になること。所要時間・追加データ容量を記録する。
3. Python本体・venv・モデル・キャッシュが、DigiViewerの専用領域 `%LOCALAPPDATA%\com.digiviewer.app\species-option\` 内に置かれること。写真の管理・公開ソフトや写真フォルダーには置かれないこと。
4. `venv\pyvenv.cfg` の `include-system-site-packages = false` と、Python本体の場所が同じ専用領域内であることを確認する。
5. 手順2のPATH・Python関連レジストリ・既存Pythonの状態を再確認し、種名推測導入前と変わらないこと。管理者権限やGPUドライバーの追加を求められたら実施せず報告する。
6. 「有効にする」を押すと種名推測ボタンが現れること。アプリを終了・起動しても有効状態が残ること。

失敗した場合は表示全文と専用領域 `tmp\error.log` を記録する。グローバルなpip install、PATH変更、ドライバー追加で回避せず、原因を報告する。

## 5. 実写真の判定と人による確定

1. 写真を表示し、「種名推測」を開く。対象の写真とファイル名が一致すること。比較表示でもアクティブな1枚だけが対象であること。
2. 日本の写真では地域補正をオン、日本以外・不明ではオフにして判定する。
3. 上位5候補、相対スコア、写真全体での順位、切り出しの支持数、国内記録の有無が表示されること。スコアを正解確率と誤表記しないこと。
4. 鳥・昆虫・不鮮明な写真を含め、画像名、CPU/GPU、補正の有無、処理時間、上位5件、わかる範囲で正解が何位かを記録する。正解が1位でないだけで動作不良としない。
5. 候補を「種名欄に入れる」だけではファイル名・画像内容が変わらないこと。和名未登録なら学名が入ること。
6. コピーした写真だけで「この写真のファイル名に追加」を実行し、対象だけが改名されること。既存仕様どおり同名RAWがある場合はRAWも改名されることを確認する。
7. 判定中にダイアログを閉じて別の写真を開いても、古い結果を新しい写真に適用しないこと。
8. RAW・HEICだけを指定した場合、対応外の説明が出てクラッシュしないこと。

## 6. オフライン・停止・復旧

- 導入完了後にネットワークを切断し、CPUで判定できること。写真の外部送信・APIキー入力・有料サービス登録を求めないこと。
- 「無効にする」でボタンが消え、アプリ再起動後も無効のまま、標準機能は使えること。
- 再有効化だけならモデルを再取得しないこと。
- 判定終了後に専用Pythonが残らず、GPU/RAMの使用が落ち着くこと。
- テスト環境で導入中または判定中にアプリを終了し、専用Python/uvが残らないこと。再起動・再導入で復旧できること。
- 日本の記録だけ未取得の場合は地域補正なしで使え、その状態が説明されること。環境で再現できない異常系は「未実施」とする。

## 7. 任意のNVIDIA GPU確認

対応GPU・ドライバーがすでにあるPCだけで行う。無効化 → NVIDIA版で再導入 → 有効化する。同じ写真でCPUとGPUを試し、表示される実行方式・所要時間・候補を比較する。GPU未使用・エラー時のCPU再試行も確認する。新たなドライバーやCUDA Toolkitの導入は行わない。GPUがない場合は「対象外」と報告する。

## 8. 同居と削除範囲

両ソフトがあるPCでは、別々の写真コピーを使用して両方を同時起動する。片方の起動・終了・種名推測の切り替えで他方が止まったり設定が変わったりしないこと。

DigiViewerの「追加データを削除」を実行し、専用の `species-option` だけが削除されることを確認する。写真、RAW、`.digiviewer` のレビュー、通常のDigiViewer設定・サムネイル、相手ソフトの設定・公開データは残ること。削除後も通常の写真表示が動くこと。

同じ写真フォルダーを意図して両ソフトで開いた場合、写真の改名・移動は共有される実ファイルへの変更として見える。これはソフト同士の依存ではない。自動同期や相手ソフトへの通知・更新を期待しない。

## 報告形式

- 使用ソースzip／インストーラーのファイル名・SHA-256、画面の版
- PC構成、単体PC／同居PC、既存Pythonの有無
- 各項目: 合格／不合格／未実施／対象外
- CPU必須の結果、GPUは対象条件と結果
- PATH・Python登録の導入前後差分、専用データの保存先・容量
- 写真ごとの結果と処理時間（機能確認であり、一般的な精度保証ではない）
- 不具合の再現手順、画面表示、ログ
- 最後に残した状態（未導入／導入済み無効／有効）

合格の必須条件は「単体で動く」「CPUで判定できる」「利用者の確認前に写真を変更しない」「システムのPython環境を変えない」「無効化・削除後も標準機能が動く」。不合格や未実施の必須項目があれば、Windows対応確認済みとして配布しない。
