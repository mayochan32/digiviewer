# 0.6.0 独立性・版番号の確認結果

確認日: 2026-09-22。対象はDigiViewerの現行作業ツリーと写真の管理・公開ソフトの作業ツリー。Windows実機はこの確認の対象外。

## 結論

両者はそれぞれ単独で利用できる構成。DigiViewerが相手ソフトのインストール・起動・設定・データベース・ローカルHTTPサーバーを要求する実装、逆方向の実行依存は確認されなかった。同じPCでのインストールも妨げない。今回誤って追加した公開・管理画面側の変更と専用実行環境は撤去済み。

同じ写真フォルダーを利用者が選んだ場合、改名・移動・削除は同じ実ファイルへの操作として双方から見える。これは共有サービスや自動連携ではなく、通常のファイル共有。変更競合を防ぐ仕組みを新設したものではない。

## 確認した境界

| 項目 | DigiViewer | 写真の管理・公開ソフト |
|---|---|---|
| 起動 | Tauriアプリ。配布アプリの実行にはNode.js/Rust/相手ソフト不要 | 自身のNode/Astro構成で起動・ビルド |
| 種名推測 | 自身の設定、Tauriコマンド、埋め込んだPythonスクリプト | 種名推測の組み込みなし |
| AI実行環境 | アプリ専用ローカルデータのspecies-option内 | 作成していた追加環境を撤去 |
| 写真・レビュー | 利用者が開いた写真、.digiviewer、DigiViewerのキャッシュ | 自身のselected/public/overrides/data等 |
| 設定 | DigiViewer固有の設定とアプリ識別子 | 自身の設定ファイル |
| HTTP | 本機能に共有HTTPサーバーなし。localhost:1420は開発用Viteだけ | 自身の管理サーバー127.0.0.1:8787 |
| 相手への参照 | observations.json、taxa.yml、管理API、相手の固定パス参照なし | DigiViewerコマンド、保存領域、API参照なし |

DigiViewerの既存の地図表示にはOpenStreetMapへの通信がある。種名推測の初回導入では公式配布サイトとGBIFからダウンロードする。これらは相手ソフトへの依存とは別で、種名推測の写真アップロードや共有バックエンドは実装していない。

紹介文や旧マニュアルにあるプロジェクトの背景説明・画面写真の出典は実行依存ではない。READMEの将来の連携を示唆する文は、独立したソフトであることが明確な説明へ修正した。公開ソフト側に残るreportsは過去の測定記録で、どちらのアプリも実行に必要としない。

## バージョン

前回の実装では0.5.5のままだった。既存CHANGELOGの「機能追加はyを上げる」方針に従い、0.6.0へ変更した。

package.json、package-lock.json（ルートおよびpackagesルート）、Cargo.toml、Cargo.lock（DigiViewer項目のみ）、tauri.conf.json、画面の初期表示を統一。アプリの正式表示はCargoのパッケージバージョンを使用する。アプリ識別子com.digiviewer.appは維持し、既存設定の引き継ぎを妨げない。

以前の配布物と旧版マニュアルは0.5.5の履歴として維持。READMEで、旧配布物には新機能が入っていないことを明記。未作成のWindows 0.6.0インストーラーへのリンクを新設していない。

## 検証結果

- Nodeの独立性・版番号テスト: 2件合格。
- Rustの標準テスト: 13件合格。モデルを導入するテスト1件は通常実行ではignored。
- DigiViewer 0.6.0フロントエンド: ビルド成功。
- 写真の管理・公開ソフト: DigiViewerの起動に依存せずビルド成功（9,301ページ）。
- 種名推測の専用Python導入・CPU/MPS実写真判定は前回の専用テストで別途成功。通常実行のignoredを合格として数えていない。
- ソース参照・子プロセス起動・保存先・依存パッケージ・削除範囲を確認。

この確認で相互依存は見つからなかったが、Windows実機の導入・ドライバー互換性まで確認済みという意味ではない。Windowsの単体PCと同居PCで確認する項目はwindows-0.6.0-verification.mdに記載した。
