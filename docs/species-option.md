# 種名推測（任意の追加機能）

DigiViewer単体で動く機能です。写真公開サイトやその管理ページ、Node.jsサーバーには接続しません。インストール済みのDigiViewerアプリだけで導入・切り替え・判定できます。

## 使い方

1. DigiViewerの右上にある「設定」を開きます。
2. 「種名推測（無料の追加機能）」の「無料の追加機能を導入」を押します。
3. 導入が終わったら「有効にする」を押します。
4. 設定を閉じ、写真を表示して「種名推測」を押します。比較表示ではアクティブな写真1枚が対象です。
5. 日本で撮影した写真なら「日本で撮影した写真として生息記録を考慮する」を選択し、「この写真を判定」を押します。
6. 候補を比較し、必要なら「この候補を種名欄に入れる」を押します。まだファイル名は変わりません。
7. 種名を確認・編集したうえで「この写真のファイル名に追加」を押すと、その写真の名前に追加します。DigiViewerの既存の命名処理を使うため、対応するRAWファイルが同じ場所にある場合は一緒に改名されます。

候補を選ばず閉じてもかまいません。写真を自動で同定済みにすることはありません。現在は和名辞書が小さいため、和名未登録の候補は学名で表示します。登録済みの和名以外を推測で補いません。

## 対応環境

- Apple Silicon Mac: CPU / MPS（内蔵GPU）。専用Pythonの導入と実写真の両方式を確認済み。
- Windows x64: CPU / 任意でNVIDIA CUDA 12.8。Windows 11 x64実機でCPU版の導入・判定・削除を確認済み。NVIDIA版は依存関係解決のみ確認し、実機動作は未検証。
- Intel Mac、Windows ARM、Linux、通常のブラウザー版は今回の対象外。

PythonやNode.jsを利用者が別途インストールする必要はありません。モデル・分類データは約4.5GBで、導入時の空き容量15GB以上、メモリ16GB以上が目安です。GPUは必須ではありません。WindowsのCPU版ならGPUドライバーの追加なしで試せます。NVIDIA版は対応ドライバーがすでにあるPC用で、本機能がドライバーを導入することはありません。

Windows CPU版の実測では専用領域全体が約10.38GiBでした。判定時間はRyzen 9 7940HSで約14〜16秒（JPEG 2枚の機能確認）で、PCと写真によって変わります。

JPEG・PNG・WebP・BMP・TIFF・GIFを受け付けます。RAW・HEICは対象外です。GIFは先頭フレームを使います。150MBを超えるファイルや大きすぎる画像はエラーになることがあります。

## 導入・無効化・削除

初期状態は未導入・無効です。設定から「無効にする」で利用を停止し、「有効にする」で再開します。「追加データを削除」は専用Python・仮想環境・モデル・キャッシュだけを削除します。写真・レビュー結果・通常の設定は残ります。

保存先はTauriが提供するDigiViewer専用のローカルアプリデータ領域の `species-option/` です。インストール先や公開サイトのフォルダーは使いません。Python本体とvenvを同じ専用領域に置き、既存のPython・PATH・シェル設定・Windowsレジストリを変更しません。uvのWindows登録と実行ファイルの共通フォルダーへの設置も無効にしています。実行時は専用Pythonを絶対パスで起動します。

venvは依存関係の分離であり、OS全体を隔離する仮想マシンではありません。専用領域の手動移動はせず、別PCでは再導入してください。

導入エラーは設定画面に表示します。無効状態で再導入すると再試行できます。日本の記録だけ取得できなかった場合は、地域補正なしで使えます。通常の判定完了後はPythonプロセスが終了し、モデルをメモリに常駐させません。

### Windowsで判定中にアプリを終了する場合の注意

**判定が完了してからDigiViewerを終了してください。** 判定中にアプリを強制終了すると、専用Pythonプロセスが残り、メモリやCPUを使用し続けることがあります。Windows実機では2個のプロセスが5秒以上残ることを確認しました。自然に終了するまでの時間と、通常のウィンドウを閉じる操作での挙動は未確認です。この制約は0.6.0では注意事項として許容しています。

残った場合は、タスクマネージャーの「詳細」で実行ファイルの場所を確認し、`%LOCALAPPDATA%\com.digiviewer.app\species-option\` 配下にある専用Pythonプロセスだけを終了してください。既存のPythonや他のアプリのPythonを一括終了しないでください。専用Pythonを停止した後、DigiViewerを再起動して判定できることは確認済みです。

## 無料・通信

有料API、APIキー、登録アカウントは不要です。導入時だけ公式のGitHub（uv/Python）、PyPI/PyTorch、Hugging Face、GBIFから公開データを取得します。判定時はダウンロード済みのデータで処理し、写真・ファイル名・撮影地は外部送信しません。

uv 0.12.17と配布ハッシュ、BioCLIP 2と分類埋め込みのrevision、主要ライブラリのバージョンを固定しています。判定モデルは任意のリモートコードを実行せず、`weights_only=True` で読み込みます。

## 数値と根拠

上位5候補と、残りの候補のスコア合計を表示します。スコアは校正された正解確率ではなく、候補間の相対値です。写真が不鮮明、対象が小さい、複数の生物がいる、モデルに対象種がない場合は、高スコアでも誤る可能性があります。

写真全体に0.5、中央と四隅の60%サイズの切り出し5箇所にそれぞれ0.1の重みを付けて統合します。別々の写真をまとめる機能ではありません。日本の記録を考慮する場合、国内GBIF記録に学名の一致がない候補の重みを0.1倍にしますが、候補からは除外しません。部分的な取得結果で地域補正はしません。

根拠として、写真全体での順位、切り出し5箇所のうち上位5件に入った数、GBIF国内記録数と取得日を表示します。切り出しは独立した観測ではありません。国内記録は飼育・栽培・誤記録を含み、学名の表記差・異名も完全には扱いません。模様・体形について根拠のない説明文を生成することはありません。

## 開発時の確認

- `npm run build`: TypeScriptとフロントエンドのビルド
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`: 既存処理と初期状態・環境分離・同時実行防止を確認
- `native_install_and_offline_inference` は通常は実行しないテスト。明示した一時領域に専用Pythonを導入し、CPU/GPUの実写真判定と写真不変を確認する。`DIGIVIEWER_SPECIES_SMOKE_BASE` と `DIGIVIEWER_SPECIES_SMOKE_PHOTO` が必要で、モデル取得には通信・容量を使う
- Macで確認用アプリを作成し、DigiViewerの「設定」に導入操作が表示されることを確認

Mac・Windowsとも今回の動作確認は一般的な精度評価ではありません。Windows CPU版の確認範囲と未検証項目は[Windows検証結果の確認と受け入れ判断](windows-0.6.0-review.md)を参照してください。NVIDIA版のGPUドライバー互換性と速度は実機未検証です。
